# Gap Analysis Prompt

## Objective

Generate a comprehensive Gap Analysis Report by analyzing the completed Requirement Analysis and validating the completeness, consistency, and quality of all project requirements.

---

## Input Sources

Use the following inputs:

### Primary Input

- RequirementAnalysis.md

### Supporting Documents (if required)

- BRD
- PRD
- FRD
- User Stories
- Business Rules
- Figma Designs
- Screenshots
- API Documentation
- Architecture Documents

---

## Analysis Scope

Review the available requirements and identify:

- Missing Functional Requirements
- Missing Business Requirements
- Missing Business Rules
- Missing Acceptance Criteria
- Missing Validation Rules
- Missing User Roles
- Missing UI Behaviors
- Missing API Requirements
- Missing Workflows
- Missing Alternate Flows
- Missing Exception Flows
- Missing Error Handling
- Missing Non-Functional Requirements
- Missing Security Requirements
- Missing Accessibility Requirements
- Missing Performance Requirements
- Conflicting Requirements
- Duplicate Requirements
- Ambiguous Requirements
- Undefined Dependencies
- Requirement Risks
- Business Risks

---

## Deliverable

Generate a comprehensive Gap Analysis Report using the structure defined in:

- `02-templates/GapAnalysis.md`

---

## Report Requirements

The report should include:

- Executive Summary
- Requirement Gaps
- Business Rule Gaps
- Workflow Gaps
- Validation Gaps
- UI Gaps
- API Gaps
- Non-Functional Gaps
- Assumptions
- Risks
- Clarification Questions
- Recommendations

---

## Output

Save the generated report as:

`07-outputs/GapAnalysis.md`

---

## Expected Outcome

The generated Gap Analysis should:

- Improve requirement quality.
- Identify requirement ambiguities.
- Highlight missing information.
- Reduce downstream testing risks.
- Prepare validated requirements for Test Planning and Test Design.
- Be suitable for Business Analysts, Product Owners, Developers, and QA Teams.
