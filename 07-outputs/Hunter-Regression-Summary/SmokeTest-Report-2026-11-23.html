1 · Log Harvest on a Checked-In Hunting booking

Fixed
STG had zero Hunting bookings in Approved status, so the suite's existing self-heal helper (which checks in an eligible Approved booking) had nothing to work with — every Hunting booking was Pending, Checked Out, or Cancelled.
Fix: extended ensureCheckedInHuntingBooking() to fall back to an eligible Pending Hunting booking with a past/current check-in date, approve it, then check it in. Also wired the existing Given a 'Checked In' Hunting booking exists precondition into the scenario, which had simply never been added.

2 · TC_GST_004 — Edit Guest Profile mandatory fields

Test updated
The test cleared Full Name and Email, then expected both to show a required-field error. Verified live on STG: Email Address has no required-field asterisk on this form and the app does not validate it on submit — only Full Name is enforced. This is a conflict between the test's assumption and actual app behavior, not a broken locator.
Decision (per your instruction): updated the test case to match confirmed app behavior rather than filing it as a defect. verifyMandatoryFieldErrors() now asserts only the Full Name error, with a comment recording why Email Address was dropped.

Fix: verifySignedWaiverEmptyStateMessage() now accepts either valid empty-state message instead of only the generic one.
