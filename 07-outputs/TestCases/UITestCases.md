## Cross-Cluster / Cross-Document Duplicate Resolution (Mandatory Final Pass)

Per `03-standards/testing-standards.md`'s "Cross-Document Duplicate Resolution (Mandatory Final Pass)", all 4 cluster outputs were checked against each other (not just against `FunctionalTestCases.md`) before finalizing:

- **1 cross-cluster duplicate found and removed:** the original `TC_UI_RANCH_011` ("RANCH - Initial Settings Step - DocuSeal Waiver Template dropdown opens and displays available template options", written by the AUTH/SA/RANCH subagent) duplicated `TC_UI_WAIVER_003` ("Waiver - Ranch Wizard Initial Settings - Docuseal Template dropdown opens and lists available templates", written independently by the STAFF/HARVEST/WAIVER subagent) — both subagents covered the same Docuseal-template dropdown on the Ranch wizard's Initial Settings step without visibility into each other's output. `TC_UI_RANCH_011` was removed; `TC_UI_WAIVER_002`/`TC_UI_WAIVER_003` were kept under the WAIVER module since Docuseal template configuration is a WAIVER-owned feature (FR-WAIVER-002) that happens to be hosted inside the RANCH wizard's UI. The RANCH module's remaining 21 rows were renumbered sequentially (`TC_UI_RANCH_001`-`TC_UI_RANCH_021`) to close the resulting ID gap; the former `TC_UI_RANCH_012` is unchanged, the former `TC_UI_RANCH_020` is now `TC_UI_RANCH_019`.

- Each subagent additionally ran its own duplicate check against `FunctionalTestCases.md`'s 324 existing rows before finalizing (checked by Test Scenario + Expected Result content, not just Test Case ID) — see each module's entries in "Clarifications Required" below for the specific rows checked and the classification-review items raised where a UI case shares a trigger/screen with an existing FUNCTIONAL row. No case in this document restates a FUNCTIONAL row's business-rule/outcome objective; every row here is scoped to a genuinely UI-only objective (layout/rendering/navigation/responsive/presentation).
- `TC_UI_GUIDE_010`'s Requirement ID was corrected from a placeholder `TBD` to `FR-GUIDE-002` (the closest FR governing the Guide portal screen this case exercises) during final assembly, since the case (accessible column-header markup) does not actually depend on the unresolved GAP-BR-03 visibility-scope question that justified `TBD` on `TC_UI_GUIDE_005`. This is recorded for transparency, not a perfect FR match — see Clarifications.
