# 2. Product Overview

RanchOps Pro (IGZ Marquis Hunting App) is a multi-tenant ranch/hunting-property operations platform. A **Super Admin** manages the platform and onboards **Ranch Admins**, each scoped to one or more ranches (tenants). Within a ranch, **Ranch Admin** users configure the property (rooms, pricing, animal categories, waiver templates, turnover/check-in settings), manage bookings for hunters and guests, assign **Guides**, track harvested animals against a **Harvest Log** with tag allocation and regulatory-compliance capture, generate post-stay invoices, and manage liability waivers via a Docuseal e-signature integration. A distinct **Guide** role has operational, restricted access (its own bookings, harvest logging, invoicing) without administrative or pricing-management access.

This description is built from the 54 in-scope JIRA stories/tasks; where IMHA-71's supplementary Feature List supplies additional platform-level framing (multi-tenancy model, Super Admin/Ranch Admin/Guide role structure, external integrations), it is cited as corroborating context, consistent with the task's instruction to fold it into relevant sections rather than treat it as a standalone requirement.

## 8.1 Authentication & Access (FR-AUTH)

**FR-AUTH-001 — Login (Password-Based)** — **CONFIRMED 2026-11-02**
Source: IMHA-82, IMHA-91 (both JIRA Status: Done)
A login page at `/login` presents an Email field and a masked Password field, with a "Sign In" button. On submission, the system validates: (1) the entered username/email exists, (2) the entered password is correct, and (3) the account's role matches the expected role for the login context (e.g., Ranch Admin role validated for Ranch Admin access). ## 8.3 Ranch Configuration (FR-RANCH)

**FR-RANCH-001 — Ranch Create/Edit Wizard (5 steps)**
Source: IMHA-1, IMHA-84 (Duplicate Report F16: fully merged — IMHA-84 restates IMHA-1's wizard structure near step-for-step)
Super Admin uses a 5-step wizard (Basic Information → Ranch Details → Rooms → Initial Settings → Review & Submit) to create or edit a ranch:
- *Basic Information:* Ranch Name, Full Address, County, Contact Phone, Contact Email (all required).
- *Ranch Details:* Property Size (acres, required), Ranch Description (required), Website URL (optional), Huntable Animals (required multi-item list, at least one required), Stands (optional list), Available Add-ons (optional list).
- *Rooms:* room table with Room Name, Beds (stepper), Cost per Night ($), and remove action.
- *Initial Settings:* Turnover Days (required dropdown), Waiver Signing Deadline (required dropdown), Waiver Expiration days (required, default 365), Harvest Report Email Frequency (required dropdown), Time Zone (required searchable dropdown), DocuSeal Waiver Template (dropdown).
- *Review & Submit:* summary cards per step; "Create Ranch" (create mode) or "Save Changes" (edit mode).
Values persist across back/forward navigation; each step enforces its required fields before allowing "Next." Edit mode pre-populates all 5 steps from the existing ranch record, shows a loading/error state on fetch failure, and allows editing/adding/removing any field, animal, stand, add-on, or room, with a success toast and redirect on save.

# 9. Business Rules

- **Login role validation:** a login attempt is accepted only when the username/email exists, the password is correct, and the account's role matches the expected role for the login context (FR-AUTH-001; IMHA-82, IMHA-91).
- **Tenant data isolation:** each Ranch Admin/Guide sees only their assigned ranch's data; no cross-ranch visibility (corroborated by IMHA-71 AUTH-03; no in-scope JIRA story contradicts it).
- **Ranch Admin role restriction:** Ranch Admin cannot create Ranches or other Ranch Admin users; where permitted to touch another Ranch Admin's record, a Ranch Admin may edit only the Full Name field (FR-SA-002; IMHA-91, IMHA-92).
- **Turnover-day blocking:** bookings cannot be created on a date marked as a Turnover Day for that ranch (FR-RANCH-002; IMHA-72, IMHA-1).
- **One invoice per booking (and per unlinked harvest):** a second invoice cannot be created once one exists for a booking or an unlinked harvest (FR-INVOICE-003; IMHA-90, IMHA-191).
- **Pricing hidden from Guide role at both UI and API levels:** a Guide-authenticated API call must not return pricing data (FR-GUIDE-001; IMHA-137).
- **Mandatory waiver signing extends to non-hunter guests**, not just hunters (FR-WAIVER-004; IMHA-160).
- **Address is mandatory in Hunter Information** during New Booking (FR-BOOK-004; IMHA-164).
- **Guide assignment is capped at 4 guides per booking**, and only Super Admin/Ranch Admin can manage guide assignments on a booking — Guides themselves cannot (FR-BOOK-006; IMHA-171).
- **Harvest tag consumption:** creating each harvest consumes one allocated tag for that ranch (FR-HARVEST-004; IMHA-97).
- **Category-conditional harvest field/result display:** when a specific animal category (e.g., Deer) is selected, that category's associated fields/results display accordingly — confirmed as a shared mechanism across FR-HARVEST-006 (Other-category field replication) and FR-HARVEST-007 (animal-name-vs-species display) per the Duplicate Report's F29 resolution (IMHA-89, IMHA-136, IMHA-184).

# 10. End-to-End Workflows

**10.1 Ranch Onboarding (Super Admin):** Super Admin creates a ranch via the 5-step wizard (FR-RANCH-001) → creates a Ranch Admin and assigns them to the ranch (FR-SA-001) → Ranch Admin authenticates via the confirmed password-based login (FR-AUTH-001) and is scoped to that ranch only, per the session established at FR-AUTH-002.

**10.2 Booking Lifecycle:** User creates a booking (FR-BOOK-001), selecting ranch/dates/rooms/hunter & guest details/guide(s) (FR-BOOK-006) → booking triggers Docuseal waiver dispatch (FR-WAIVER-001) to all listed hunters/guests (FR-WAIVER-004) → hunters/guests may also receive a personal-details email form (FR-GUEST-004), with results auto-reflected in the Guest Directory (FR-GUEST-001) → booking auto-checks-in on start date and auto-checks-out on end date (FR-BOOK-008), with manual edit available throughout per its status (FR-BOOK-002) → signed waivers display in UI, and can be resent post check-in if needed (FR-WAIVER-002, FR-WAIVER-003) → once checked in, a Harvest Log can be created/edited (FR-HARVEST-001), consuming tag allocation (FR-HARVEST-004) and applying category-conditional fields (FR-HARVEST-006/007) → once checked out, an invoice is generated, previewed, downloaded, and (if needed) discarded/replaced, subject to the one-invoice-per-booking rule and Invoiced-tag UI (FR-INVOICE-001/002/003).

**10.3 Guide Operational Flow:** Guide authenticates via the confirmed password-based login (FR-AUTH-001) → sees assigned/ranch bookings on their dashboard (corroborated by IMHA-71 GUIDE-01, unresolved visibility scope per that document's own flagged ambiguity) → can submit a new booking request (FR-BOOK-007) → can access Harvest Log and invoicing for selected bookings (FR-HARVEST-001, FR-INVOICE-001) without seeing pricing data (FR-GUIDE-001), but can see Whitetail Deer tag counts (FR-GUIDE-002).
